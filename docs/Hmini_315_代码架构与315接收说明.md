# Hmini_315 代码架构与 315 接收说明

本文档随 `Hmini_315` 仓库维护。

本文对应整理后的 Arduino Mega 2560 草图，涵盖315 MHz接收、标准SBUS转发、模式隔离、传感器以及本地水桨和舵机控制。

## 2. 串口与当前运行模式

| 接口 | 用途 | 参数 | 当前是否启用 |
|---|---|---|---|
| `Serial` | USB串口监视器 | 115200 | 是 |
| `Serial1` | IMU | 115200 | 是 |
| `Serial2` / D16 / TX2 | Arduino→PX4标准SBUS | 100000、8E2 | 是 |
| `Serial3` / D15 / RX3 | 315接收器OUT | 9600、8N1 | 是 |

主草图当前使用完整外设模式：

```cpp
#define RX315_BENCH_TEST_ONLY 0
```

当前值为 `0`。因此：

- `setup()`初始化USB、315、SBUS、SD、Bar30、IMU、ESC和舵机；
- 四路ESC初始化后输出1490 us中立值，舵机输出1000/2000 us安全位置；
- 执行器运行期总锁上电始终为`DISARMED`，不会保存到EEPROM；
- 从STOP安全进入WATER且IMU、深度数据新鲜时自动变为`ARMED`；
- `Serial2`持续以标准SBUS向PX4发送通道或failsafe帧。

`RX315_BENCH_TEST_ONLY`仍是编译期宏，不能由串口修改。执行器总锁由手柄STOP/WATER状态机控制；315失联、模式变化或传感器超时都会自动重新锁定。

## 3. 已确认的315输入协议

315 MHz 是手柄到接收器的无线载波频率。接收器解调后，从OUT引脚输出9600 baud、8N1串口数据。

每帧固定24字节：

```text
00 | AD AD AD AD AD | FE | 10 | CRC | Data'[12] | BD DB BD
```

| 位置 | 长度 | 含义 |
|---|---:|---|
| `00` | 1 | 帧前导/分隔 |
| `AD×5` | 5 | 同步序列；解析器至少接受3个 |
| `FE` | 1 | 帧头标识 |
| `10` | 1 | 后续负载长度为16字节 |
| `CRC` | 1 | CRC-8，多项式`0x31` |
| `Data'[12]` | 12 | 加扰后的96位控制数据 |
| `BD DB BD` | 3 | 固定帧尾 |

CRC只覆盖线上加扰后的 `Data'[12]`。解扰掩码为：

```text
BD DB BD DB BD DB BD DB BD DB BD DB
```

逐字节执行：

```text
Data[i] = Data'[i] XOR mask[i]
```

解扰后的96位数据布局：

| 内容 | 位区间 | 位宽 |
|---|---:|---:|
| 通道0～3 | 0～43 | 每通道11位 |
| 通道4～9 | 44～79 | 每通道6位 |
| 帧序号 | 80～90 | 11位，0～2047循环 |
| 保留字段 | 91～95 | 5位 |

前4个通道映射为 `1000 + raw×1000/2047`，后6个通道映射为 `1000 + raw×1000/63`。

### 已实测通道映射

下表由实际手柄测试确认。当前将`ch[0]`定义为Yaw；`ch[3]`尚未分配SBUS控制功能，但仍保留其原始通道值并放入SBUS CH4，便于后续扩展。

| 通道 | 手柄操作 | 范围/档位 | PX4语义或用途 |
|---|---|---|---|
| `ch[0]` | 右摇杆左右 | 左1000 ～ 中1500 ～ 右2000 | Yaw / 偏航 |
| `ch[1]` | 右摇杆上下 | 下1000 ～ 中1500 ～ 上2000 | Pitch / 俯仰 |
| `ch[2]` | 左摇杆上下 | 下1000 ～ 中1500 ～ 上2000 | Throttle / 油门 |
| `ch[3]` | 左摇杆左右 | 左1000 ～ 中1500 ～ 右2000 | 未分配；保留原始值 |
| `ch[4]` | 左扳机 SA | 松开1000、按下2000 | 辅助开关 |
| `ch[5]` | 左三档开关 SB | 后1000、中1492、前2000 | 三档开关 |
| `ch[6]` | 右三档开关 SC | 后1000、中1492、前2000 | 三档开关 |
| `ch[7]` | 右扳机 SD | 松开1000、按下2000 | 辅助开关 |
| `ch[8]` | 左扳机 SE | 松开1000、按下2000 | 辅助开关 |
| `ch[9]` | 右旋钮 SI | 左1000 ～ 右2000 | 连续辅助通道 |

三档开关的中位显示为1492是正常的：该类通道只有6位精度，原始中位值31按当前公式映射后约为1492，而非严格1500。

## 4. `Hmini_315.ino`

### 全局对象与变量

- `sensor`：MS5837/Bar30深度计。
- `dataFile`、`SDdata`、`FileName`：SD日志。
- `esc1/esc2`：D7前、D10后两路深度/俯仰水桨ESC。
- `esc3/esc4`：D9左、D8右两路前进/偏航水桨ESC。
- `servo_left/right`：左右舵机。
- `Depth/Depth0/Temp`：相对深度、深度零点和温度。
- `yaw_315`：CH1水下偏航指令。
- `pitch_315`：CH2输入；沿用旧名称，实际语义为前后推进Surge。
- `depth_d_315`：CH3超过1050后线性映射得到的0.0～1.0 m深度目标；≤1050为垂直水桨停机区。
- `angle`：CH10映射得到的舵机目标量。
- `servo_motion_target_us`：一次完整动作锁定的端点，运动期间不随旋钮改变。
- `servo_output_us`：经过非阻塞斜坡限速后实际发送给左舵机的脉宽；右舵机使用`3000-servo_output_us`。
- `phi/the/psi/d_att`：横滚、俯仰、航向和角速度。
- `errSum`：四路PID积分状态。

### `SDwrite()`

将累积的 `SDdata` 写入已打开文件，然后清空字符串。

### `writeNeutralOutputs()`

把四个ESC写为1490 us，并让左右舵机回到1000/2000 us。上电、未解锁、串口锁定和任一安全条件失效时都会使用该输出。

### `updateServoOutputs()`

WATER已解锁且舵机空闲时，将当前`angle`复制到`servo_motion_target_us`并锁定本次动作。之后每20 ms以500 us/s移动，直到完整到达该端点；运动期间旋钮的任何变化均被忽略，不允许中途反向。到位后停留500 ms，再读取旋钮当时的最终状态决定是否开始下一次完整动作，中途变化不会排队。单次计算的时间跨度最多按100 ms计，避免主循环偶发阻塞后产生大幅跳变。STOP、AIR、失联或传感器异常仍立即使用安全位置。

该策略降低频繁反向造成的冲击，但舵机到位后仍保持力矩。如果1000/2000 us对应的位置超过机构机械限位，仍可能堵转、发热甚至损坏，必须通过断开连杆或限流方式校准安全端点。

### `setup()`

当前调用流程：

```text
Serial.begin(115200)
  -> rx315Begin()
  -> sbusOutputBegin()
  -> 绑定ESC与舵机
  -> writeNeutralOutputs()
  -> 执行器总锁保持DISARMED
  -> 初始化IMU、SD和Bar30
```

### `loop()`

当前调用流程：

```text
rx315Update()
  -> updateControlState()
  -> sbusOutputUpdate()
  -> serialConsoleUpdate()
  -> 更新IMU与深度
  -> enforceActuatorOutputSafety()
  -> 每50 ms执行控制或中立输出
```

主循环始终先更新RX315、控制模式和SBUS隔离。每50 ms只有在执行器总锁为`ARMED`、WATER模式、入水联锁已解开、315新鲜、IMU新鲜和深度新鲜全部满足时才执行水下控制，否则持续写入中立输出。

### `serialEvent1()`

逐字节读取IMU的 `Serial1` 数据并交给 `packet_decode()`。

## 5. `RX315.ino`

这是当前正式315接收模块，不再叫“diagnostic mode”。

### 对外接口

| 函数 | 作用 |
|---|---|
| `rx315Begin()` | 初始化 `Serial3@9600,8N1` 并打印启动信息 |
| `rx315Update()` | 清空接收缓冲区、逐字节解析，并每秒打印统计 |
| `rx315Channel(index)` | 返回指定通道映射后的1000～2000值；越界返回1500 |
| `rx315RawChannel(index)` | 返回指定通道原始11位/6位值；越界返回0 |
| `rx315HasFreshFrame()` | 已经收到有效帧且最近一帧不超过200 ms时返回true |
| `rx315LastFrameAgeMs()` | 返回最近有效帧年龄；尚无有效帧时返回`0xFFFFFFFF` |

这些接口只提供状态，不会执行断联保护或控制输出。

### 持久状态

`rx315_raw_channel[10]` 和 `rx315_pwm_channel[10]` 保存最近一个有效帧的通道，因此后续水桨映射和SBUS发送可以直接读取，不再依赖打印函数中的临时数组。

模块还保存：

- 总接收字节数；
- 有效帧数；
- CRC错误数；
- 帧尾错误数；
- 同步错误数；
- 根据11位序号估算的丢帧数；
- 最近有效帧时间；
- 当前序号和5位保留字段。

### `rx315Crc8()`

按初值0、多项式 `0x31` 计算CRC-8。调用时输入必须是加扰后的12字节线上数据。

### `rx315ExtractBits()`

从解扰后的12字节中按低位优先提取连续位字段，用于恢复10个通道、帧序号和保留位。

### `rx315Map11BitToPwm()` / `rx315Map6BitToPwm()`

分别把0～2047和0～63转换为1000～2000。

### `rx315DecodeData()`

执行：

```text
BD/DB解扰
  -> 提取ch[0]～ch[9]原始值
  -> 映射为1000～2000
  -> 提取帧序号和保留字段
  -> 统计序号跳变造成的丢帧
```

只有CRC和帧尾均正确时才会调用。

### `rx315HandlePayload()`

收满16字节负载后：

1. 检查固定帧尾 `BD DB BD`；
2. 对12字节 `Data'` 计算CRC；
3. 全部正确后调用 `rx315DecodeData()`；
4. 更新有效帧计数和最近有效时间。

坏帧只增加错误计数，不覆盖最近一次有效通道。

### 手柄断连状态

接收器在手柄关机后仍可能产生噪声字节，因此不能以 `Serial3.available()` 判断连接状态。模块只以“最近一次CRC和帧尾均正确的有效帧”为依据：超过200 ms没有有效帧即视为断连。

- 连接成功时仅输出一次：`EVENT,rx=CONNECTED,...`。
- 从已连接状态变为断连时仅输出一次：`EVENT,rx=DISCONNECTED,age_ms=...,...`。
- 断连期间继续在后台读取并统计噪声，但默认不输出周期日志。
- 重新收到有效帧后重新输出一次连接事件。
- 断连会切换STOP、本地执行器中立并使SBUS持续发送带failsafe标志的安全帧。

### `rx315ConsumeByte()`

逐字节状态机：

```text
等待00
  -> 等待至少3个AD及FE
  -> 等待长度10
  -> 收取16字节负载
  -> rx315HandlePayload()
  -> 回到等待00
```

遇到错误后调用 `rx315ResetParser()`，在下一帧重新同步。

### 串口输出

RX315模块自身只输出连接/断连事件。通道值和链路统计由`SerialConsole.ino`按命令输出：

- `channels`或`watch channels on`：物理手柄名称及水下控制映射；
- `watch link on`：合并后的RX315错误计数与SBUS发送状态；
- `watch all off`：恢复仅事件输出。

## 6. `sbus.ino`

`sbus.ino`是主草图中的SBUS输出模块，不是可独立烧录的库示例。该文件不定义自己的`setup()`或`loop()`，也不创建`SbusRx`；新315接收器是唯一输入源，`Serial2`只负责向PX4发送。

### 对外接口

| 函数 | 作用 |
|---|---|
| `sbusOutputBegin()` | 初始化`bfs::SbusTx`，并立即发送一帧已定义的failsafe数据 |
| `sbusOutputUpdate()` | 每14 ms根据315链路状态发送通道帧或failsafe帧 |

### SBUS帧、串口与电气层

SBUS是把最多16个模拟通道压入一帧的串行协议，而不是10路独立PWM脉冲。标准帧为25字节：帧头`0x0F`、22字节的16路11位通道数据、1字节状态位、帧尾`0x00`。库在`SbusTx::Write()`中完成位打包、状态位写入和25字节发送。

标准SBUS串口格式为100000 baud、8E2，即8个数据位、偶校验和2个停止位；每个字节在线上占12位。故一帧在线时长为：

```text
25 bytes × (1 start + 8 data + 1 parity + 2 stop) / 100000 baud
= 300 / 100000 s
= 3 ms
```

标准SBUS还使用反相逻辑。Mega 2560的硬件UART不能自行反相，因此库在Mega上输出的是未反相的100000 baud、8E2 UART；板卡的SOUT路径必须负责反相和3.3 V电平适配，才能接入PX4 RC/SBUS输入。

### 通道数值范围与转换

SBUS每个模拟通道在帧内占11位，编码层允许的完整范围是0～2047。常规遥控器的±100%行程通常使用172～1811；0～2047是约±150%扩展行程才会使用的范围。PX4随后会将收到的SBUS原始数值换算为`RC_CHANNELS`中常见的约1000～2000值。

因此：

```text
常规SBUS范围：172～1811，中位约992
```

本机PX4实测常规SBUS编码和`RC_CHANNELS`的关系为：

```text
SBUS 172  -> PX4 982
SBUS 992  -> PX4 1494
SBUS 1811 -> PX4 2004
```

为了让PX4端显示精确对齐到1000、1500、2000，本项目使用针对该PX4板卡测得的补偿编码：

```text
PX4目标1000 -> SBUS编码201
PX4目标1500 -> SBUS编码1002
PX4目标2000 -> SBUS编码1802
```

`sbus.ino`以`rx315Channel()`已经计算出的1000～2000 PWM语义值为输入；但`data.ch[]`仍必须存放SBUS编码值，不能直接写入1000～2000。发送端采用以物理中位为分界的两段线性编码：

| 315通道 | 输入范围和中位 | SBUS编码 | 目标PX4显示 |
|---|---:|---|---|
| `ch[0]～ch[3]` | 1000～2000，中位1500 | 1000→201，1500→1002，2000→1802 | 1000、1500、2000 |
| `ch[4]～ch[9]` | 1000～2000，中位1492 | 1000→201，1492→1002，2000→1802 | 1000、1500、2000 |

两段映射使输入端的低位、中位和高位都精确落在对应的补偿编码点；代码中的`+ input_span / 2`用于整数除法前的四舍五入。6位三档开关在接收器侧的中位仍是1492，但发送SBUS时会单独对齐到PX4端的1500。

SBUS CH1～CH10保持315通道原顺序；CH11～CH16固定为补偿中位1002，数字CH17和CH18关闭。

补偿编码是针对当前PX4固件和板卡实测得到的，而非所有SBUS设备通用的常量。若更换PX4硬件、固件或SBUS驱动，应重新记录三点实测值并调整`SBUS_PX4_MIN/MID/MAX`。

### 发送周期

`SBUS_OUTPUT_PERIOD_MS = 14UL`表示主循环每至少14 ms发送一帧，即约71.4 Hz。该值是常规SBUS刷新频率的工程选择，不是由172～1811数值范围推导出来的：它大于单帧3 ms线上时间，因此不会让Serial2发送缓冲持续堆积，同时足以让PX4获得连续稳定的RC输入。

315接收器的24字节输入在9600 baud下单帧约需25 ms，因此SBUS有时会重复发送最近一次有效315通道。重复帧不会增加手柄的实际更新率，但能保持PX4端的SBUS流连续；每收到新的有效315帧后，下一次SBUS周期就会使用新值。

常量中的`U`表示无符号整数；`UL`表示无符号长整数。发送周期使用`uint32_t`和`millis()`的差值比较，即使`millis()`约49天回绕，`now - sbus_last_output_ms`的无符号减法仍能正确工作。

### 断联输出与状态位

SBUS输出分为三种状态：

- `ACTIVE`：315在线且为AIR模式，转发实时10通道，`lost_frame=false`、`failsafe=false`；
- `NEUTRAL`：315在线且为STOP/WATER，姿态回中、油门和六个辅助通道置低，`lost_frame=false`、`failsafe=false`；
- `FAILSAFE`：启动时尚无有效315帧或超过200 ms没有有效帧，使用同样的安全通道值，但置位`lost_frame=true`、`failsafe=true`。

`NEUTRAL`状态的具体通道值为：

- Roll、Pitch和Yaw为补偿中位1002；
- Throttle为补偿最低201；
- 六个辅助通道为补偿最低201；
- `lost_frame=false`、`failsafe=false`。

真正的`FAILSAFE`状态复用上述安全通道值并把两个状态位置为true。SBUS状态字节中，`lost_frame`表示本帧存在丢帧条件，`failsafe`表示发送端进入明确的失控保护状态；PX4据此设置`input_rc.rc_failsafe`。主动选择STOP/WATER不再伪装成链路失效，因此不会持续触发PX4 RC Failsafe报警。

注意，`NEUTRAL`只保证PX4收到最低油门RC输入，不保证已经解锁的PX4输出绝对0 PWM；台架测试仍必须拆桨并保持PX4未解锁。

## 7. `WaterControl315.ino` 与 `YawCtrl.ino`

`Marine_Remote_315()` 以原始315水下控制算法为基线，并接入当前10通道接收接口：

- CH1写入`yaw_315`，作为左右水平推进桨的直接偏航差动量；
- CH2写入`pitch_315`，变量名沿用旧代码但实际作为前后推进量；
- CH3≤1050时关闭前后垂直水桨，超过1050后映射为0.0～1.0 m深度目标；
- CH10写入`angle`请求；空闲时锁存端点，运动中忽略变化，左右舵机以500 us/s输出互补脉宽；
- `depth_d_315` 与Bar30深度形成深度外环；
- IMU姿态和角速度参与横滚、俯仰、航向控制；
- `esc1/esc2` 控制深度和俯仰；
- `esc3/esc4` 控制前进和偏航；
- 运行数据写入SD。

CH3底部≤1050是明确的垂直水桨停机区：`esc1/esc2`固定1490 us，深度与俯仰闭环均不参与。这样可避免台面和水面测试中压力漂移、深度零点或姿态误差导致水桨转动；代价是在水下拨到底不会主动上浮。超过1050后才进入绝对深度闭环。

CH7右三档SC选择AIR/STOP/WATER。STOP立即中立四路ESC并把舵机送到安全位置；每次从STOP进入WATER都会重置联锁，只有CH1/CH2位于1470～1530、CH3≤1050且IMU与深度数据新鲜时才自动启用。315失联、切回STOP/AIR、IMU超时或深度数据无效都会中立全部本地输出并把运行期总锁恢复为`DISARMED`。

`PID_outloop()`包含深度、横滚、俯仰和航向四路计算。`u_depth`和`u_pitch`混入前后垂直水桨，`u_yaw`混入左右水平推进桨；`u_roll`当前没有对应执行器分配，因此横滚闭环尚未实际生效。

`YawCtrl.ino` 保留 `TD()`、`fst()`、`sgn()` 和 `PID_outloop()`。旧2.4 GHz专用的 `PID_Remote()` 已移出正式控制链；同时修正了 `ki=0` 时积分限幅除零的问题。

## 10. 当前调用流程

```text
315接收器OUT
  -> Mega D15 / Serial3@9600
  -> rx315Update()
  -> rx315ConsumeByte()
  -> 帧头与长度同步
  -> rx315HandlePayload()
       ├─ 帧尾检查
       └─ CRC-8检查
  -> rx315DecodeData()
       ├─ BD/DB解扰
       ├─ 保存raw[10]
       ├─ 保存pwm[10]
       └─ 保存序号/统计
  -> USB串口显示
  -> sbusOutputUpdate()
       ├─ fresh: raw[10]映射为SBUS CH1～CH10
       ├─ stale: 生成安全通道和failsafe标志
       └─ Serial2 TX/D16每14 ms发送标准SBUS
  -> PX4 RC/SBUS输入
```

AIR模式下流程到PX4原生RC/SBUS输入结束，本地水下执行器保持安全输出。315在线时，STOP/WATER模式向PX4发送`NEUTRAL`安全中立帧；WATER模式在本地联锁与传感器条件满足后才进入水下控制。只有315真实断联才发送`FAILSAFE`。

### CH14输出帧计数

旧自定义PX4协议的12字节载荷中包含11位`frame_count`。当前标准SBUS桥接将该诊断功能保存到SBUS CH14（`data.ch[13]`，数组下标从0开始）：`sbus_output_frame_count`会在每次`sbus_tx.Write()`前递增；上电首帧、正常帧和failsafe帧均计入，并通过`& 0x07FF`在2047后回绕到0。

CH14保存的是原始协议计数，而非1000～2000的PWM控制量。14 ms发送周期下约每28.7 s回绕一次。不得将CH14分配给PX4飞行模式、AUX passthrough、参数调节或执行器；CH11～CH13与CH15～CH16保持补偿中位，CH17与CH18保持关闭。

SBUS ACTIVE/NEUTRAL/FAILSAFE发生变化时，USB串口仅输出一次`EVENT,sbus=...`。Serial2上的二进制SBUS帧仍保持14 ms发送周期。需要周期检查累计发送帧数时，通过`watch link on`显式开启`LINK`输出；USB日志开关不影响Serial2。

正常情况下输入来源应为SBUS、通道值随手柄变化且`rc_failsafe=false`；关闭手柄超过200 ms后应看到`rc_failsafe=true`，重新连接后恢复。

通道映射、模式隔离和软件联锁已经实现。后续仍需保持台架模式完成模式日志与端点检查，再在断桨条件下验证推进方向、舵机方向、传感器超时保护和实际动力安全。
