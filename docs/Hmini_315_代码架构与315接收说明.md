# Hmini_315 代码架构与 315 接收说明

本文档随 `Hmini_315` 仓库维护。

本文对应整理后的 Arduino Mega 2560 草图。当前阶段实现并测试 315 MHz 接收器的数据接收、校验、解扰、通道解析，以及通过标准SBUS向PX4转发10个手柄通道。水桨、电机、舵机和完整传感器流程仍保持禁用。

## 1. 当前目录结构

```text
embedded/
├─ Hmini_315/
│  ├─ Hmini_315.ino          主程序入口、硬件对象和台架模式
│  ├─ RX315.ino              正式315接收与协议解析模块
│  ├─ sbus.ino               Arduino→PX4标准SBUS输出模块
│  ├─ WaterControl315.ino     保留的315水桨控制算法
│  ├─ YawCtrl.ino             跟踪微分器和水下姿态/深度PID
│  ├─ imu_data_decode.*       IMU数据内容解码
│  ├─ packet.*                IMU串口帧与CRC16解码
│  └─ MS5837.*                Bar30深度传感器驱动
├─ RX315_Diagnostics/
│  └─ RX315_Diagnostics.ino   独立的原始脉冲/UART抓包工具
└─ legacy/
   ├─ Hmini_315_before_cleanup.ino.txt
   ├─ HZ315_legacy.ino.txt
   └─ Radio_2.4G_and_315_original.ino.txt
```

Arduino IDE 会将 `Hmini_315` 目录中的所有 `.ino` 标签页合并编译，所以 `Hmini_315.ino` 可以直接调用 `RX315.ino` 中的函数。`legacy` 文件使用 `.txt` 后缀且位于草图目录外，不会参与编译。

## 2. 串口与当前运行模式

| 接口 | 用途 | 参数 | 当前是否启用 |
|---|---|---|---|
| `Serial` | USB串口监视器 | 115200 | 是 |
| `Serial1` | IMU | 115200 | 台架模式下否 |
| `Serial2` / D16 / TX2 | Arduino→PX4标准SBUS | 100000、8E2 | 是 |
| `Serial3` / D15 / RX3 | 315接收器OUT | 9600、8N1 | 是 |

主草图只有一个模式开关：

```cpp
#define RX315_BENCH_TEST_ONLY 1
```

当前值为 `1`。因此：

- `setup()` 执行 `Serial.begin()`、`rx315Begin()`和`sbusOutputBegin()`；
- `loop()` 执行 `rx315Update()`和`sbusOutputUpdate()`；
- SD、Bar30、IMU、ESC和舵机均不会初始化；
- `Serial2`持续以标准SBUS向PX4发送通道或failsafe帧。

通道含义和PX4 SBUS转发已经实现，但水桨映射和动力安全检查尚未完成，因此当前仍不应将该宏改为 `0`。

## 3. 已确认的315输入协议

315 MHz 是手柄到接收器的无线载波频率。接收器解调后，从OUT引脚输出9600 baud、8N1串口数据。

每帧固定24字节：

```text
00 | AD AD AD AD AD | FE | 10 | CRC | Data'[12] | BD DB BD
```

| 位置 | 长度 | 含义 |
|---|---:|---|
| `00` | 1 | 帧前导/分隔 |
| `AD×5` | 5 | 同步序列；解析器至少接受3个 |
| `FE` | 1 | 帧头标识 |
| `10` | 1 | 后续负载长度为16字节 |
| `CRC` | 1 | CRC-8，多项式`0x31` |
| `Data'[12]` | 12 | 加扰后的96位控制数据 |
| `BD DB BD` | 3 | 固定帧尾 |

CRC只覆盖线上加扰后的 `Data'[12]`。解扰掩码为：

```text
BD DB BD DB BD DB BD DB BD DB BD DB
```

逐字节执行：

```text
Data[i] = Data'[i] XOR mask[i]
```

解扰后的96位数据布局：

| 内容 | 位区间 | 位宽 |
|---|---:|---:|
| 通道0～3 | 0～43 | 每通道11位 |
| 通道4～9 | 44～79 | 每通道6位 |
| 帧序号 | 80～90 | 11位，0～2047循环 |
| 保留字段 | 91～95 | 5位 |

前4个通道映射为 `1000 + raw×1000/2047`，后6个通道映射为 `1000 + raw×1000/63`。

### 已实测通道映射

下表由实际手柄测试确认。`ch[0]～ch[3]` 的顺序正好与PX4既有协议定义的 Roll、Pitch、Throttle、Yaw 一致，后续转换为标准SBUS时应保持此顺序。

| 通道 | 手柄操作 | 范围/档位 | PX4语义或用途 |
|---|---|---|---|
| `ch[0]` | 右摇杆左右 | 左1000 ～ 中1500 ～ 右2000 | Roll / 横滚 |
| `ch[1]` | 右摇杆上下 | 下1000 ～ 中1500 ～ 上2000 | Pitch / 俯仰 |
| `ch[2]` | 左摇杆上下 | 下1000 ～ 中1500 ～ 上2000 | Throttle / 油门 |
| `ch[3]` | 左摇杆左右 | 左1000 ～ 中1500 ～ 右2000 | Yaw / 偏航 |
| `ch[4]` | 左扳机 SA | 松开1000、按下2000 | 辅助开关 |
| `ch[5]` | 左三档开关 SB | 后1000、中1492、前2000 | 三档开关 |
| `ch[6]` | 右三档开关 SC | 后1000、中1492、前2000 | 三档开关 |
| `ch[7]` | 右扳机 SD | 松开1000、按下2000 | 辅助开关 |
| `ch[8]` | 左扳机 SE | 松开1000、按下2000 | 辅助开关 |
| `ch[9]` | 右旋钮 SI | 左1000 ～ 右2000 | 连续辅助通道 |

三档开关的中位显示为1492是正常的：该类通道只有6位精度，原始中位值31按当前公式映射后约为1492，而非严格1500。

## 4. `Hmini_315.ino`

### 全局对象与变量

- `sensor`：MS5837/Bar30深度计。
- `dataFile`、`SDdata`、`FileName`：SD日志。
- `esc1～esc4`：前、后、左、右四个水桨ESC。
- `servo_left/right`：左右舵机。
- `Depth/Depth0/Temp`：相对深度、深度零点和温度。
- `roll_315/pitch_315/depth_d_315`：未来完成通道映射后使用的水桨控制输入；当前保持中立值。
- `phi/the/psi/d_att`：横滚、俯仰、航向和角速度。
- `errSum`：四路PID积分状态。

### `SDwrite()`

将累积的 `SDdata` 写入已打开文件，然后清空字符串。台架模式下不会执行。

### `writeNeutralOutputs()`

把四个ESC写为1490 us，并让左右舵机回到1000/2000 us。台架模式下舵机未绑定，因此该函数不会被调用。

### `setup()`

当前调用流程：

```text
Serial.begin(115200)
  -> rx315Begin()
  -> sbusOutputBegin()
  -> 因RX315_BENCH_TEST_ONLY=1而return
```

关闭台架模式后才会继续初始化IMU、SD、Bar30、ESC和舵机。

### `loop()`

当前调用流程：

```text
rx315Update()
  -> sbusOutputUpdate()
  -> 因RX315_BENCH_TEST_ONLY=1而return
```

关闭台架模式后的保留流程会读取IMU和深度，并每50 ms根据 `rx315HasFreshFrame()` 选择水桨控制或中立输出。但当前还没有把 `rx315Channel()` 映射到 `roll_315/pitch_315`，所以不能直接恢复动力。

### `serialEvent1()`

完整模式下逐字节读取IMU的 `Serial1` 数据并交给 `packet_decode()`。当前台架模式没有初始化 `Serial1`。

## 5. `RX315.ino`

这是当前正式315接收模块，不再叫“diagnostic mode”。

### 对外接口

| 函数 | 作用 |
|---|---|
| `rx315Begin()` | 初始化 `Serial3@9600,8N1` 并打印启动信息 |
| `rx315Update()` | 清空接收缓冲区、逐字节解析，并每秒打印统计 |
| `rx315Channel(index)` | 返回指定通道映射后的1000～2000值；越界返回1500 |
| `rx315RawChannel(index)` | 返回指定通道原始11位/6位值；越界返回0 |
| `rx315HasFreshFrame()` | 已经收到有效帧且最近一帧不超过200 ms时返回true |
| `rx315LastFrameAgeMs()` | 返回最近有效帧年龄；尚无有效帧时返回`0xFFFFFFFF` |

这些接口只提供状态，不会执行断联保护或控制输出。

### 持久状态

`rx315_raw_channel[10]` 和 `rx315_pwm_channel[10]` 保存最近一个有效帧的通道，因此后续水桨映射和SBUS发送可以直接读取，不再依赖打印函数中的临时数组。

模块还保存：

- 总接收字节数；
- 有效帧数；
- CRC错误数；
- 帧尾错误数；
- 同步错误数；
- 根据11位序号估算的丢帧数；
- 最近有效帧时间；
- 当前序号和5位保留字段。

### `rx315Crc8()`

按初值0、多项式 `0x31` 计算CRC-8。调用时输入必须是加扰后的12字节线上数据。

### `rx315ExtractBits()`

从解扰后的12字节中按低位优先提取连续位字段，用于恢复10个通道、帧序号和保留位。

### `rx315Map11BitToPwm()` / `rx315Map6BitToPwm()`

分别把0～2047和0～63转换为1000～2000。

### `rx315DecodeData()`

执行：

```text
BD/DB解扰
  -> 提取ch[0]～ch[9]原始值
  -> 映射为1000～2000
  -> 提取帧序号和保留字段
  -> 统计序号跳变造成的丢帧
```

只有CRC和帧尾均正确时才会调用。

### `rx315HandlePayload()`

收满16字节负载后：

1. 检查固定帧尾 `BD DB BD`；
2. 对12字节 `Data'` 计算CRC；
3. 全部正确后调用 `rx315DecodeData()`；
4. 更新有效帧计数和最近有效时间；
5. 最多每100 ms打印一次通道。

坏帧只增加错误计数，不覆盖最近一次有效通道。

### 手柄断连状态

接收器在手柄关机后仍可能产生噪声字节，因此不能以 `Serial3.available()` 判断连接状态。模块只以“最近一次CRC和帧尾均正确的有效帧”为依据：超过200 ms没有有效帧即视为断连。

- 连接成功时仅输出一次：`RX315_FLAG,CONNECTED,...`。
- 从已连接状态变为断连时仅输出一次：`RX315_FLAG,DISCONNECTED,last_age_ms=...,...`。
- 断连期间仍在后台读取并统计噪声，但停止输出每秒的 `RX315_STATUS`，避免串口刷屏。
- 重新收到有效帧后重新输出一次连接提示，并恢复正常通道/状态显示。

本机制目前只提供通信状态提示；水桨中立、PX4 failsafe等动作留待后续断联保护阶段实现。

### `rx315ConsumeByte()`

逐字节状态机：

```text
等待00
  -> 等待至少3个AD及FE
  -> 等待长度10
  -> 收取16字节负载
  -> rx315HandlePayload()
  -> 回到等待00
```

遇到错误后调用 `rx315ResetParser()`，在下一帧重新同步。

### 串口输出

有效通道：

```text
RX315_VALID,frames=...,seq=...,ch=...,crc_errors=...,tail_errors=...,sync_errors=...
```

每秒状态：

```text
RX315_STATUS,bytes=...,valid=...,crc_errors=...,tail_errors=...,sync_errors=...,seq_lost=...,last_age_ms=...
```

`RX315_STATUS` 仅在已连接时每秒输出；断连时改为单次 `RX315_FLAG,DISCONNECTED`。

## 6. `sbus.ino`

`sbus.ino`是主草图中的SBUS输出模块，不是可独立烧录的库示例。该文件不定义自己的`setup()`或`loop()`，也不创建`SbusRx`；新315接收器是唯一输入源，`Serial2`只负责向PX4发送。

### 对外接口

| 函数 | 作用 |
|---|---|
| `sbusOutputBegin()` | 初始化`bfs::SbusTx`，并立即发送一帧已定义的failsafe数据 |
| `sbusOutputUpdate()` | 每14 ms根据315链路状态发送通道帧或failsafe帧 |

### 通道转换

SBUS库的`data.ch[]`使用约172～1811的原始SBUS范围，而不是1000～2000微秒值。因此模块直接读取`rx315RawChannel()`：

- `ch[0]～ch[3]`由0～2047映射到172～1811；
- `ch[4]～ch[9]`由0～63映射到172～1811；
- SBUS CH1～CH10保持315通道原顺序；
- CH11～CH16固定为中位992，数字CH17和CH18关闭。

### 断联输出

当`rx315HasFreshFrame()`为true时，发送实时10通道并清除SBUS的`lost_frame`和`failsafe`位。启动阶段或超过200 ms没有有效315帧时仍持续发送：

- Roll、Pitch和Yaw为中位992；
- Throttle为最低172；
- 六个辅助通道为最低172；
- `lost_frame=true`、`failsafe=true`。

Mega 2560上的SBUS库通过`Serial2 TX/D16`输出100000 baud、8E2的未反相UART。板卡SOUT到PX4 RC/SBUS输入之间必须已有SBUS反相和适当的电平转换。

## 7. `WaterControl315.ino` 与 `YawCtrl.ino`

`Marine_Remote_315()` 保留原来的水下控制算法：

- `roll_315/pitch_315` 控制左右水平推进；
- `depth_d_315` 与Bar30深度形成深度外环；
- IMU姿态和角速度参与横滚、俯仰、航向控制；
- `esc1/esc2` 控制深度和俯仰；
- `esc3/esc4` 控制前进和偏航；
- 运行数据写入SD。

手柄物理操作与 `ch[0]～ch[9]` 的对应关系已经确认，但尚未决定哪些通道写入 `roll_315`、`pitch_315` 和 `depth_d_315`，因此当前仍未给这些水桨控制变量赋通道值。

`YawCtrl.ino` 保留 `TD()`、`fst()`、`sgn()` 和 `PID_outloop()`。旧2.4 GHz专用的 `PID_Remote()` 已移出正式控制链；同时修正了 `ki=0` 时积分限幅除零的问题。

## 8. 诊断工具

`RX315_Diagnostics.ino` 是独立草图，不参与 `Hmini_315` 编译。通过下面的宏选择：

```cpp
#define RX315_DIAGNOSTIC_MODE RX315_DIAGNOSTIC_RAW_CAPTURE
```

- `RX315_DIAGNOSTIC_RAW_CAPTURE`：使用D15/PCINT9采集最多160个电平脉宽，串口输入 `c` 启动。
- `RX315_DIAGNOSTIC_UART_PROBE`：使用 `Serial3@9600` 输出原始十六进制字节。

只有接收器协议再次发生变化或需要排查物理信号时才烧录该草图。

## 9. 已归档的旧代码

- `Hmini_315_before_cleanup.ino.txt`：整理前完整主草图快照。
- `HZ315_legacy.ino.txt`：旧4800 baud、`AA×5 + FE F1`协议；与当前接收器不兼容。

## 10. 当前调用流程

```text
315接收器OUT
  -> Mega D15 / Serial3@9600
  -> rx315Update()
  -> rx315ConsumeByte()
  -> 帧头与长度同步
  -> rx315HandlePayload()
       ├─ 帧尾检查
       └─ CRC-8检查
  -> rx315DecodeData()
       ├─ BD/DB解扰
       ├─ 保存raw[10]
       ├─ 保存pwm[10]
       └─ 保存序号/统计
  -> USB串口显示
  -> sbusOutputUpdate()
       ├─ fresh: raw[10]映射为SBUS CH1～CH10
       ├─ stale: 生成安全通道和failsafe标志
       └─ Serial2 TX/D16每14 ms发送标准SBUS
  -> PX4 RC/SBUS输入
```

当前流程到PX4的原生RC/SBUS输入结束，不进入水桨控制。

## 11. QGC验证与下一阶段边界

验证时手柄不连接电脑，只保持无线发射；PX4通过USB连接Windows电脑。在QGC中进入`Vehicle Setup → Radio`观察通道，不使用只识别电脑USB/HID设备的`Joystick`页面。

可在QGC的MAVLink Console运行：

```text
listener input_rc -n 20
```

正常情况下输入来源应为SBUS、通道值随手柄变化且`rc_failsafe=false`；关闭手柄超过200 ms后应看到`rc_failsafe=true`，重新连接后恢复。

SBUS转发阶段完成后，水桨控制仍需另行决定：

- 哪些通道写入`roll_315/pitch_315/depth_d_315`；
- 水下控制所需的通道反向、中位死区和开关阈值；
- 执行器启用前的动力安全检查。
