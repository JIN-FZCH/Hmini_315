# 🧰 Hmini 315 使用、安全与调试指南

本文集中说明 Hmini 315 的硬件接线、操作流程、安全联锁和诊断方法。接收协议、位域与代码调用关系见[代码架构与 315 接收说明](Hmini_315_代码架构与315接收说明.md)。

## ⚠️ 1. 上电前检查

> [!WARNING]
> 完整外设模式会初始化 ESC 和舵机。首次上电、修改通道映射或调整输出参数后，必须拆除全部桨叶再测试。

上电前逐项确认：

- 全部桨叶已经拆除；
- 舵机在 1000～2000 us 全行程内不会碰撞机械限位；
- 315 接收器、Arduino 和 PX4 已共地；
- PX4 保持未解锁，并已配置合适的 RC Failsafe；
- Mega `D16 / TX2` 没有直接接入 PX4，而是经过 `SOUT` 反相和 3.3 V 电平适配；
- 首次进入 WATER 前，CH1、CH2 回中且 CH3 置于最低。

> [!CAUTION]
> STOP/WATER 下发送给 PX4 的安全中立帧会将油门通道置低，但这不等价于 PX4 电机输出端的 `0 PWM`。若 PX4 已解锁，具体机型和参数仍可能使电机保持怠速。

## 🔌 2. 硬件连接

| 起点 | 终点 | 信号 / 参数 |
|---|---|---|
| 315 接收器 `OUT` | Mega `D15 / RX3` | UART，9600 baud，8N1 |
| Mega `D16 / TX2` | 板卡 `SOUT` | 未反相 SBUS UART，100000 baud，8E2 |
| 板卡 `SOUT` | PX4 `RC/SBUS IN` | 反相、3.3 V 电平适配后的标准 SBUS |
| Arduino `GND` | 接收器及 PX4 `GND` | 必须共地 |
| Mega USB | 电脑 | 调试串口，115200 baud |
| 前深度水桨 ESC | Mega `D7` | `esc1`，深度 / 俯仰 |
| 后深度水桨 ESC | Mega `D10` | `esc2`，深度 / 俯仰 |
| 左偏航水桨 ESC | Mega `D9` | `esc3`，前进 / 偏航 |
| 右偏航水桨 ESC | Mega `D8` | `esc4`，前进 / 偏航 |
| 左舵机 | Mega `D4` | 1000～2000 us |
| 右舵机 | Mega `D6` | 与左舵机互补输出 |

标准 SBUS 使用反相逻辑，而 Arduino Mega 的硬件 UART 不会自动反相。板卡 `SOUT` 负责逻辑反相与电平适配，不能默认用裸 UART TX 替代。

## 🚀 3. 编译与上传

### 📦 环境

- Arduino Mega 2560
- Arduino IDE 与 Arduino AVR Boards 支持包
- Bolder Flight Systems SBUS 库（代码使用 `sbus.h`、`bfs::SbusTx`）
- 315 MHz 接收器、带 SBUS 输入的 PX4 飞控
- QGroundControl

`Wire`、`SPI`、`SD` 和 `Servo` 为 Arduino 内置库；MS5837 驱动已包含在仓库中。

### ⬆️ 步骤

1. 使用 Arduino IDE 打开项目根目录的 `Hmini_315.ino`。
2. 开发板选择 **Arduino Mega or Mega 2560**。
3. 确认主草图使用完整外设模式：

   ```cpp
   #define RX315_BENCH_TEST_ONLY 0
   ```

4. 按“上电前检查”拆桨并检查接线、舵机行程和 PX4 状态。
5. 选择正确串口，编译并上传。
6. 以 115200 baud 打开串口监视器。

串口命令接受“换行”“回车”或“两者同时”作为行结束符；选择“无行结束符”时命令不会执行。

正常启动和模式切换时可看到类似日志：

```text
FIRMWARE,id=HMINI315_20260806_01
FIRMWARE,features=RX350,MODE_KEEP,SERVO_HOLD_2000,SURGE_CAL
EVENT,sbus=FAILSAFE,reason=STARTUP
EVENT,actuators=DISARMED,reason=STARTUP
EVENT,rx=CONNECTED,frames_ok=...,seq=...
EVENT,sbus=NEUTRAL,reason=STOP_MODE
EVENT,mode=AIR,ch7=1000,rx=CONNECTED
EVENT,sbus=ACTIVE,reason=AIR_MODE
```

每次烧录后应先核对两行`FIRMWARE`日志。当前版本必须同时包含`MODE_KEEP`和`SERVO_HOLD_2000`；如果缺少，说明板上运行的不是包含断连模式保持和舵机2秒保持的固件。

## 🎛️ 4. 控制模式与安全联锁

| CH7 / SC | 模式 | 本地执行器 | PX4 / SBUS |
|---|---|---|---|
| 后档，≤1250 | AIR | 保持安全输出 | 转发实时 CH1～CH10 |
| 中档 | STOP | 立即恢复安全输出 | 发送有效安全中立帧 |
| 前档，≥1750 | WATER | 联锁通过后启用 | 发送有效安全中立帧 |
| 315 无有效帧超过 350 ms | Failsafe | 恢复安全输出并锁定 | 置位 `lost_frame` 与 `failsafe` |

最后一帧年龄在200～350 ms之间时属于瞬断宽限：系统保持上一帧控制值和当前模式，不复位舵机、不撤销控制权限，也不切换SBUS Failsafe。若350 ms内收到新有效帧，系统无状态跳变；超过350 ms才确认失联。该机制会让真实失联保护比原先最多延后150 ms。

确认失联不会把`control_mode`改写成STOP，系统会保留最后一次AIR/STOP/WATER选择并进入独立的`RX_FAILSAFE`状态。若最后模式为AIR，SBUS仍在350 ms后进入Failsafe，但舵机保持最后位置至最后有效帧满2秒；2秒内恢复时从原位置继续跟随，持续失联超过2秒才闭合。主动切换STOP/WATER不使用该保持时间，舵机仍立即闭合。

### 🔒 WATER 入水联锁

每次从 STOP 进入 WATER 都必须重新满足以下条件：

- CH1 和 CH2 位于 1470～1530；
- CH3 ≤1050；
- 315 数据新鲜；
- IMU 数据新鲜且包含所需姿态、角速度字段；
- 深度传感器已初始化且数据新鲜。

检查通过后，本地执行器自动由 `DISARMED` 变为 `ARMED`，不需要 USB 串口 ARM 命令。以下任一情况都会恢复安全输出并重新锁定：

- 315 失联；
- 切换到 STOP 或 AIR；
- IMU 超时；
- 深度数据无效或超时。

故障恢复后必须重新触发入水联锁。可以先回到 STOP 再进入 WATER；也可以在 WATER 中让入口安全条件离开后重新满足。若传感器恢复时控制杆一直停留在安全区，系统不会自行重新解锁。

### 🌊 水下控制

- CH1 控制左右水平推进桨的差动偏航。
- CH2 沿用变量名 `pitch_315`，实际用于前后推进 Surge。
- CH3 ≤1050 时，前后垂直水桨强制为 1490 us，深度和俯仰闭环均不参与。
- CH3 >1050 后映射为 0～1 m 的绝对深度目标，深度与俯仰 PID 参与垂直水桨控制。

CH3 的底部停机区用于避免台面或水面测试时因气压漂移、深度零点或姿态误差导致垂直水桨转动。相应地，机器人在水下将 CH3 拨到底时不会主动上浮，只能依靠自身浮力。

### ⚙️ 舵机连续角度控制

舵机只在AIR模式且315链路有效时响应CH10。右旋钮输出1000～2000 us的连续位置指令，代码采用实时目标跟随和输出限速：

- 每 20 ms 读取一次当前 CH10，并将其作为最新目标；
- 舵机输出以 `SERVO_SLEW_US_PER_SECOND = 500` us/s 的最大速度追赶目标，完整行程最快约 2 秒；
- 旋钮停在中间位置时，舵机平滑停在对应角度；
- 移动过程中旋钮反向时，舵机立即开始限速反向，不会先走完旧目标；
- 不再锁存整段动作，也不再执行端点停留；
- STOP或WATER会绕过斜坡，立即回到安全位置；AIR中失联先保持最后位置2秒，持续失联后再立即回安全位置。

输出限速只能限制移动速度，不能防止机械堵转。必须确认 1000～2000 us 全行程不会让连杆碰撞物理限位。

## 🕹️ 5. 通道映射

| PX4 / SBUS | Arduino | 手柄操作 | 数值范围 |
|---|---|---|---:|
| CH1 — Yaw | `ch[0]` | 右摇杆左右 | 1000～2000 |
| CH2 — Pitch | `ch[1]` | 右摇杆上下 | 1000～2000 |
| CH3 — Throttle | `ch[2]` | 左摇杆上下 | 1000～2000 |
| CH4 — 未分配 | `ch[3]` | 左摇杆左右 | 1000～2000 |
| CH5 | `ch[4]` | 左扳机 SA | 1000 / 2000 |
| CH6 | `ch[5]` | 左三档开关 SB | 1000 / 1492 / 2000 |
| CH7 | `ch[6]` | 右三档开关 SC | 1000 / 1492 / 2000 |
| CH8 | `ch[7]` | 右扳机 SD | 1000 / 2000 |
| CH9 | `ch[8]` | 左扳机 SE | 1000 / 2000 |
| CH10 | `ch[9]` | 右旋钮 SI | 1000～2000 |

`1492` 是 6 位辅助通道映射后的正常物理中位；发送 SBUS 时会单独补偿，使 PX4 端显示约为 `1500`。

手柄当前输出的CH2/SURGE实测范围为 `1126 / 1621 / 2000`。接收层采用三点分段校准，将其恢复为 `1000 / 1500 / 2000` 后再提供给水下控制和SBUS。由于手柄正向原始行程已在2000处截断，软件校准可以恢复端点和中位，但不能恢复被截断的输入分辨率；条件允许时仍应修复手柄端偏移。

CH4 目前未绑定任何控制功能，但代码仍保留并转发其原始值。PX4 不应将 CH4 绑定到飞行模式、参数或执行器。

> [!WARNING]
> SBUS CH14 是 11 位循环帧计数，仅用于链路诊断，不是 PWM 控制通道。请勿将其分配给飞行模式、AUX passthrough、参数调节或任何执行器。

## 🛡️ 6. 失控保护

系统只把通过 CRC、帧头和帧尾校验的数据视为有效输入。接收器仍有噪声、但最后一帧有效数据已经超过350 ms时，Arduino会持续发送Failsafe SBUS帧：

- Roll、Pitch、Yaw 回中；
- Throttle 置于最低；
- CH5～CH10 置于最低；
- `lost_frame=true`；
- `failsafe=true`。

重新收到有效帧后，输出根据当前模式恢复：

- AIR：恢复 `ACTIVE`，转发实时通道；
- STOP/WATER：恢复 `NEUTRAL`，发送姿态回中、油门最低且两个失控标志为 `false` 的有效帧。

本地执行器总锁不写入 EEPROM，每次上电都从 `DISARMED` 开始。

## 🖥️ 7. 串口诊断

周期日志默认关闭，可按需使用以下命令：

| 命令 | 输出 |
|---|---|
| `help` | 命令帮助 |
| `status` | 单次系统状态 |
| `channels` | 单次手柄与控制映射 |
| `watch channels on/off` | 开启 / 关闭 5 Hz `CHANNELS` |
| `watch link on/off` | 开启 / 关闭 1 Hz `LINK` |
| `watch all off` | 关闭全部周期输出 |

`watch channels on` 只在 315 数据有效时维持 5 Hz 输出。手柄断连时会输出一次 `CHANNELS,rx=DISCONNECTED,...` 后暂停，并在重新连接后自动恢复。

示例：

```text
CHANNELS,RSX/YAW=1500,RSY/SURGE=1500,LSY/DEPTH=1000/0.000m,LSX=1500,SA=1000,SB=1000,SC/MODE=1492/STOP,SD=1000,SE=1000,SI=1000,SERVO_REQUEST=1000:2000,SERVO_TARGET=1000:2000,SERVO_OUTPUT=1000:2000,SERVO_MOVING=0,WATER=LOCKED,ACTUATORS=DISARMED,VERTICAL=OFF
```

`RSX/RSY` 是右摇杆横 / 纵轴，`LSX/LSY` 是左摇杆横 / 纵轴；`SERVO_REQUEST` 是当前请求，`SERVO_TARGET` 是输出层正在跟踪的最新目标，`SERVO_OUTPUT` 是经过限速后的实际输出脉宽。

## 🧭 8. PX4 / QGroundControl 验证

1. 将 PX4 通过 USB 连接到电脑。
2. 在 QGroundControl 中进入 `Vehicle Setup → Radio`。
3. 将 CH7 / SC 置于 AIR，操作手柄并观察 CH1～CH10。
4. 也可以在 MAVLink Console 中运行：

   ```text
   listener input_rc -n 20
   ```

预期结果：

- AIR 且 315 在线时，CH1～CH10 随对应控件变化，`rc_failsafe=false`；
- 关闭手柄超过350 ms后，`rc_failsafe=true`；
- 恢复连接后，通道与状态自动恢复；
- STOP/WATER 且 315 在线时，收到 `failsafe=false` 的安全中立通道。

请使用 QGroundControl 的 **Radio** 页面验证 RC 数据。**Joystick** 页面用于电脑 USB/HID 手柄，不适用于本链路。

## 🔍 9. 故障排查

| 现象 | 检查项 |
|---|---|
| 完全没有输入字节 | 接收器 `OUT → D15/RX3`、供电和共地 |
| 持续出现 CRC 错误 | 波特率、电平、干扰和接收器协议版本 |
| Arduino 通道正常但 PX4 无输入 | SBUS 反相、电平适配和 PX4 RC/SBUS 端口配置 |
| PX4 中位或端点偏移 | 按实际硬件重新标定 `SBUS_PX4_MIN/MID/MAX` |
| 需要查看手柄映射 | `channels` 或 `watch channels on` |
| 需要查看链路错误计数 | `watch link on` |
| 需要抓取原始信号 | `tools/RX315_Diagnostics/RX315_Diagnostics.ino` |

诊断完成后可使用 `watch channels off`、`watch link off` 或 `watch all off` 关闭周期输出。
